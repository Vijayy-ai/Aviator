The backend Game Engine manages 3 distinct states and broadcasts them to all connected WebSocket clients simultaneously:

* **STATE 1: WAITING (e.g., 5-10 seconds)**

    * Web Frontend: Shows a progress bar/timer and allows users to place bets.
    * Mobile App (Separate connection logic): Receives prediction for the upcoming round.
* **STATE 2: FLYING (Multiplier increases)**
    * Backend broadcast every 100ms: `{"status": "flying", "current_multiplier": 1.45}`
    * Web Frontend: Renders the plane flying and updates the multiplier number on screen. Locks new bets. Allows users to click "Cash Out".
* **STATE 3: CRASHED**
    * Backend stops at the predefined crash point (e.g., 3.20x).
    * Backend broadcast: `{"status": "crashed", "crash_point": 3.20}`
    * Web Frontend: Explodes the plane instantly. Displays the crashed value in red. 
    * Backend resolves all bets, updates wallets, and immediately transitions back to STATE 1 for the next round.
